# 失败分类标签体系 (Failure Tags)

## 标签一览

| 标签 | 符号 | 含义 | 判定标准 | 责任方 |
|------|------|------|---------|--------|
| 数据问题 | `[!][数据问题]` | Mock 数据不足或表格/下拉为空 | snapshot 中目标列表/选项为空 | 前端 Mock 层 |
| 接口问题 | `[!][接口问题]` | 接口 404/500/超时 | 控制台网络面板报错或页面报错提示 | 后端 |
| 元素定位失败 | `[!][元素定位失败]` | snapshot 中找不到目标按钮/输入框 | browser_snapshot 搜不到对应 ref | 词典/源码不一致 |
| 校验不符预期 | `[!][校验不符预期]` | 红字没出现 / 出现了不该出现的错误 | 空提交后 snapshot 无 `.el-form-item__error` | 前端校验规则 |
| 路由跳转失败 | `[!][路由跳转失败]` | 点击后 URL 未变化或跳到错误页面 | snapshot URL 不符合预期 | 路由配置 |
| API参数未传递 | `[!][API参数未传递]` | 搜索/筛选/分页参数未传给接口函数 | api.ts 中函数传空 `{}` 或缺少筛选字段 | 前端代码 |
| 分页总数错误 | `[!][分页总数错误]` | 分页组件 total 与实际数据量不一致 | snapshot 中 total=0 但表格有数据，或 total 不随 CRUD 更新 | 前端/Mock 层 |
| Mock数据未变更 | `[!][Mock数据未变更]` | CRUD 操作后 Mock 层内存数据未变化 | 新增后表格行数不变，列表不刷新 | Mock 实现层 |
| 搜索无效 | `[!][搜索无效]` | 搜索条件已填入但数据未过滤 | 搜索前后表格数据完全一致 | 后端/Mock |
| 分页功能无效 | `[!][分页功能无效]` | 翻页后数据未刷新 | 点击下一页后表格数据与上一页完全相同 | 前端/Mock |
| 待确认 | `[?][待确认]` | 无法确定是 bug 还是正常行为 | 行为存疑，需人工判定 | 待分配 |

## 标签使用规则

1. **一个 SP 只打一个主标签**。如果同时有数据问题和接口问题，以**根因**为准（接口 404 导致数据为空 → 标 `[!][接口问题]`）。
2. **`[?][待确认]` 是兜底标签**，只在确实无法判断时使用，不能滥用。
3. **标签后必须附文字说明**，格式：`[!][接口问题] /api/rehab/project/add 返回 404`。
4. **★ mock 模式下的特殊处理**：
   - Mock 未实现搜索过滤 → `[?][待确认] Mock 未实现搜索过滤逻辑`（非 bug）
   - Mock 未实现 CRUD 持久化 → `[?][待确认] Mock 未实现数据持久化`（非 bug）
   - 但 api.ts 中参数没传 → `[!][API参数未传递]`（前端代码 bug，与 mock 无关）

## 严重等级

| 等级 | 条件 | 后续动作 |
|------|------|---------| 
| 🔴 阻断 | 导致 Flow 后续步骤无法执行 | Flow 中后续 SP 标记为 `[SKIP]` |
| 🟡 非阻断 | 当前 SP 失败但不影响后续 | 记录并继续 |
| 🟢 通过 | 符合预期 | 打 `[x]` |

## mock 模式 vs real-api 模式的标签选择

| 现象 | mock 模式标签 | real-api 模式标签 |
|------|-------------|-----------------|
| 搜索后数据不变 + api.ts 参数为空 | `[!][API参数未传递]` | `[!][API参数未传递]` |
| 搜索后数据不变 + api.ts 参数已传 | `[?][待确认] Mock 未实现过滤` | `[!][搜索无效]` |
| 新增后列表不变 + mock 无持久化 | `[?][待确认] Mock 未实现持久化` | `[!][接口问题]` |
| 分页 total=0 但有数据 | `[!][分页总数错误]` | `[!][分页总数错误]` |
| 翻页后数据不变 | `[!][分页功能无效]` | `[!][分页功能无效]` |
