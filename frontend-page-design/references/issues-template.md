# 争议点报告模板

> 本文件被 [SKILL.md](../SKILL.md) Step 9 引用。frontend-page-design 完成模块组装后,如果有**待用户/后端确认**的问题,**额外产出**一份 `<视图目录>/<module>/issues.md`,显式列出。

## 何时产出

满足任一条件时**必产**:
- 接口字段跟页面需求不一致(如页面要 A,接口给 B)
- 页面有"上下文依赖"但来源不明(如 `orgId` 从哪取)
- 字段类型/控件类型需要调整(如"巡楼人字段:文本框 → 下拉框")
- 接口返回字段有歧义,需要业务方解释含义

什么都没问题就**不产**。不要硬凑。

## 输出位置

```
<视图目录>/<module>/issues.md
```

## 报告生成时机

```
frontend-page-design Step 4-8: 生成代码
      ↓
frontend-page-design Step 9: 验证 + 引导测试
      ↓ 检测争议点
      ├─ 有字段不一致      → 加入 issues.md
      ├─ 有上下文依赖不明  → 加入 issues.md
      ├─ 有控件类型需调整  → 加入 issues.md
      └─ 全部一致           → 不产 issues.md,直接给最终报告
```

## 常见争议点类型

### 1. 接口字段不返回页面要的数据

```
页面要"异常老人列表"
接口只给"异常人数"
方案: 改成显示数字 / 去掉这列 / 让后端加字段
```

### 2. 字段类型 vs 控件类型不匹配

```
页面是"文本输入框",接口要 `inspectorId: number`
方案: 改成下拉选择框,调字典接口加载选项
```

### 3. 上下文依赖来源不明

```
所有接口都要 `orgId`,但页面没有这个字段
来源候选: userInfo.orgId / Pinia / localStorage / 路由参数
需要业务方确认从哪取
```

### 4. 字段名/类型变更(对接时发现)

```
旧 define.ts 用 orderType,新 YApi 改成 orderState
方案: 改 define.ts 字段名 + api.ts 函数参数,影响范围列清楚
```

### 5. 数据精度/格式不一致

```
页面要"YYYY-MM-DD",接口给毫秒时间戳
方案: 在 api.ts 函数里格式化,或在页面 computed 里转换
```

## 真实例子(灵感来源)

实战中产出过类似报告的案例:
- **某巡防模块**:3 个争议点(异常老人列表/巡楼人字段类型/机构 ID 来源),用户确认后才继续做详情页
- 这种报告让"待确认的问题"显式化,**避免代码写完才发现要返工**
